# Video animation library

`LIBRARY.md` (next to this file) holds ready-to-use items in 7 categories: Text, Video transitions, Video effects, Graphics animations, Filters, Lights and Videography styles. Each row has a name, what it does, "Best used when", a source, and a prompt that says how to make it from scratch. It is text only: no files, pictures, fonts or sounds.

## How to use it
1. Read the user's goal (the topic, the mood, the moment in the video). If they name an item, find that row in `LIBRARY.md`. If they describe a need, search the "Best used when" and "What it does" columns and offer 2 to 4 matching items, one line each.
2. Ask once for what you need to build it, if you do not know it yet: the tool (Remotion, After Effects, CapCut, plain HTML and CSS, anything), the video size (the prompts assume 1080 x 1920), their colours and fonts (optional), and the text to show.
3. Build the item from its "Prompt" column with code (Remotion, or HTML, CSS and JavaScript, or the user's own tool) as a layer for a 1080 x 1920 video at 30 fps. The prompts set no colours or fonts: use the user's own, or pick a simple clean set and say which.
4. Keep text and graphics inside the platform's safe zone (away from the app buttons on the right and the caption area at the bottom). Give anything that floats over the footage an entrance and an exit. Do not change the colours of the user's footage unless they asked for a filter.
5. Check one frame at the start, middle and end of the animation before saying it is done, and say plainly what was and was not built.
6. If two items would do the same job, pick one and say why. Keep the video lively, but use one main animation per moment, not three.

## Rules
- Only use items from `LIBRARY.md`. If nothing fits, say so and describe the closest one instead of making up a name.
- Fonts, music and sounds are not included. If the user needs them, tell them to pick ones they have the licence for.
- Keep answers short and in plain language.
